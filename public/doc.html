MRTTree — мануал по настройке тулбара

Главный принцип: весь тулбар настраивается в одном месте — createToolbarConfig({...}) в ParentPage.tsx. JSX тулбара (в ToolbarConfig.tsx) правится только при добавлении принципиально новых элементов.

1. Где что лежит

ФайлЧто содержитКогда трогать
ToolbarConfig.tsxDENSITIES, createToolbarConfig<TData>, стандартный рендер правой панелиДобавление новой кнопки / режима плотности
Tree.tsxcompactToolbarSx, обёртка renderToolbarInternalActions, поиск, ленивая загрузка, фон строкГлобальные стили тулбара, иконка/поле поиска
Types.tsMRTTreeToolbarOptions<TData>, MRTTreeProps<TData>Добавление новой опции
ParentPage.tsxВызов createToolbarConfig({...}), загрузка корнейВсе настройки тулбара
TemplateTypes.tsТип TemplateЗамена типа пользовательских данных
api.tsfetchRoots, fetchChildrenСерверная загрузка (если нужна)

Поток данных

ParentPage.tsx
  │  createToolbarConfig({ ...все настройки тулбара... })
  ▼
MRTTreeToolbarOptions<TData>
  │  → prop toolbar
  ▼
<MRTTree<Template> toolbar={toolbar} />
  │  Tree.tsx: спред в useMaterialReactTable + обёртка renderToolbarInternalActions
  ▼
MaterialReactTable рендерит тулбар

Все опции можно передать напрямую в createToolbarConfig({...}). Если не переданы — используются дефолты фабрики.

3. DENSITIES — режимы плотности

export type Density = {
  key: 'compact' | 'normal' | 'comfortable';
  label: string;
  Icon: typeof DensitySmallIcon;
  rowHeight: number;
  headerHeight: number;
  checkboxSize: 'small' | 'medium';
};

export const DENSITIES: readonly Density[] = [
  { key: 'compact',     label: 'Компактно', Icon: DensitySmallIcon,  rowHeight: 28, headerHeight: 28, checkboxSize: 'small'  },
  { key: 'normal',      label: 'Обычно',    Icon: DensityMediumIcon, rowHeight: 34, headerHeight: 32, checkboxSize: 'small'  },
  { key: 'comfortable', label: 'Просторно', Icon: DensityLargeIcon,  rowHeight: 48, headerHeight: 40, checkboxSize: 'medium' },
];

Как добавить свой режим

  1. В ToolbarConfig.tsx добавьте элемент в массив DENSITIES.
  2. Если key новый — расширьте тип Density['key'].
  3. Больше ничего менять не нужно — ParentPage автоматически циклически перебирает DENSITIES.length.

4. createToolbarConfig — аргументы

ToolbarConfigOptions = Partial<MRTTreeToolbarOptions<TData>> & { обязательные спец-поля }. То есть любую опцию тулбара можно передать напрямую. Плюс обязательны спец-поля:

АргументТипЧто делать
densityDensityТекущий режим: DENSITIES[densityIndex]
nextDensityDensityDENSITIES[(densityIndex + 1) % DENSITIES.length] — для tooltip
onDensityClick() => voidЦиклическое переключение: () => setDensityIndex(i => (i + 1) % DENSITIES.length)
selectionModeSelectionModeТекущий режим ('checkbox' | 'radio' | 'none')
onSelectionModeChange(mode) => voidОбычно setSelectionMode
showSelectionTogglebooleanПоказывать ToggleButtonGroup режима
themeMode'light' | 'dark'Текущая тема
onThemeToggle() => void() => setThemeMode(m => m === 'light' ? 'dark' : 'light')

Приоритеты значений

  1. Дефолты фабрики (enableTopToolbar: true, enableBottomToolbar: false и т.д.)
  2. Всё, что передано в options — перекрывает дефолты через ...overrides
  3. renderToolbarInternalActions: если передан пользователем — побеждает стандартный defaultRender

Добавить кнопку «Удалить выбранные» в правую панель

Поскольку renderToolbarInternalActions уже используется фабрикой, для «своей» кнопки справа нужно передать свой рендер:

createToolbarConfig<Template>({
  ...,
  renderToolbarInternalActions: ({ table }) => {
    const selectedCount = Object.keys(table.getState().rowSelection).length;
    return (
      <>
        {selectedCount > 0 && (
          <Button size="small" color="error"
            onClick={() => console.log(Object.keys(table.getState().rowSelection))}>
            Удалить ({selectedCount})
          </Button>
        )}
      </>
    );
  },
});
Передача своего renderToolbarInternalActions полностью убирает стандартные кнопки (фильтры, счётчик, плотность, тема, fullscreen) — их нужно отрисовать вручную, если они нужны.

6. Высота, отступы и центрирование контента

Где менять высоту тулбара

В Tree.tsx — константа compactToolbarSx:

const compactToolbarSx = {
  minHeight: 43,
  height: 43,
  paddingTop: 0,
  paddingBottom: 0,
  display: 'flex',
  alignItems: 'center',
  ...
};

Как сдвинуть контент по вертикали

Padding на контейнере не даёт эффекта — flex-центрирование возвращает контент в центр. Сдвиг делается через paddingBottom на Stack внутри renderToolbarInternalActions:

// Tree.tsx, внутри Stack в renderToolbarInternalActions:
height: '100%',
paddingBottom: '2px',  // ← сдвигает контент вверх на 1px
paddingBottom на StackОтступ сверху / снизу
07.5px / 7.5px (симметрично)
'2px' (текущее)6.5px / 8.5px
'4px'5.5px / 9.5px

8. Чек-лист при добавлении элемента в тулбар

  1. Нужна новая опция? → добавить в Types.ts в MRTTreeToolbarOptions<TData>.
  2. Логика кнопки (обработчик, состояние)? → в ParentPage.tsx: useState + передать в createToolbarConfig.
  3. Отрисовка кнопки? → в ToolbarConfig.tsx в defaultRender + обернуть в {flag && ...}, если нужен флаг видимости.
  4. Глобальный стиль / позиционирование? → в Tree.tsx в Stack sx.
  5. Только для страницы? → renderTopToolbarCustomActions в createToolbarConfig.

10. Как менять цвет фона строк

10.1 Механизм

В <MRTTree> передаётся функция getRowBackgroundColor(row), возвращающая CSS-цвет или undefined:

<MRTTree<Template>
  ...
  getRowBackgroundColor={(row) => /* вернуть цвет или undefined */}
/>
ВозвратРезультат
'rgba(...)', '#hex', 'hsl(...)'Строка получает этот фон
undefinedСтандартный фон (тема)

При hover и selected с кастомным фоном применяется filter: brightness() — цвет не «прыгает», но визуальная обратная связь работает.

10.2 По полю из данных

const getRowBackgroundColor = (row: Template): string | undefined => {
  switch (row.status) {
    case 'active':   return 'rgba(76, 175, 80, 0.08)';
    case 'archived': return 'rgba(158, 158, 158, 0.10)';
    case 'draft':    return 'rgba(255, 152, 0, 0.08)';
    default:         return undefined;
  }
};

10.3 По уровню вложенности

const getRowBackgroundColor = (row: Template): string | undefined => {
  if (row.managerId === null) return 'rgba(25, 118, 210, 0.08)';
  return undefined;
};

10.4 Зебра

const getRowBackgroundColor = (row: Template): string | undefined =>
  row.id % 2 === 0 ? 'rgba(0, 0, 0, 0.03)' : undefined;

10.5 Цвет прямо в данных

// TemplateTypes.ts
export type Template = {
  id: number;
  name: string;
  managerId: number | null;
  subRows?: Template[];
  color?: string; // ← цвет строки
};

// ParentPage.tsx
const getRowBackgroundColor = (row: Template): string | undefined =>
  row.color;

10.6 Готовая палитра

Оттенокrgba
Синийrgba(25, 118, 210, 0.08)
Зелёныйrgba(76, 175, 80, 0.08)
Оранжевыйrgba(255, 152, 0, 0.10)

10.7 Важно

  • Используйте rgba с низким alpha (0.04–0.12) — работает и в светлой, и в тёмной теме.
  • Сплошной цвет (#ffebee) в тёмной теме сделает текст невидимым.
  • Фон применяется ко всей строке (все <td>), потому что задаётся на <tr>.
  • Если нужен фон только одной колонки — задавайте в muiTableBodyCellProps по column.id.

11. Как загружать данные с сервера

11.1 Схема

MRTTree ожидает из ParentPage:

  • initialData: TData[] — корневые строки (один раз при монтировании);
  • loadChildren: (row) => Promise<TData[]> — ленивая загрузка детей (при первом раскрытии).

11.2 Файл api.ts

import type { Template } from './TemplateTypes';

const API_URL = '/api';

export async function fetchRoots(signal?: AbortSignal): Promise<Template[]> {
  const response = await fetch(`${API_URL}/templates/roots`, { signal });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  const data = (await response.json()) as { rows: Template[] };
  return data.rows;
}

export async function fetchChildren(parent: Template): Promise<Template[]> {
  const response = await fetch(
    `${API_URL}/templates/${parent.id}/children`,
  );
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  const data = (await response.json()) as { rows: Template[] };
  return data.rows;
}
Если сервер отдаёт массив напрямую (без обёртки { rows }) — уберите data.rows и верните (await response.json()) as Template[].

11.3 Загрузка корней в ParentPage

const [initialData, setInitialData] = useState<Template[]>([]);
const [initialLoading, setInitialLoading] = useState(true);
const [initialError, setInitialError] = useState<string | null>(null);

const loadRoots = () => {
  const controller = new AbortController();
  setInitialLoading(true);
  setInitialError(null);

  fetchRoots(controller.signal)
    .then((rows) => setInitialData(rows))
    .catch((err: unknown) => {
      if (err instanceof DOMException && err.name === 'AbortError') return;
      setInitialError(err instanceof Error ? err.message : 'Ошибка');
    })
    .finally(() => setInitialLoading(false));

  return () => controller.abort();
};

useEffect(() => {
  const cancel = loadRoots();
  return cancel;
}, []);

11.4 Передача в MRTTree

<MRTTree<Template>
  initialData={initialData}
  ...
  loadChildren={fetchChildren}
  canExpand={() => true}  // при серверной модели
  ...
/>

11.5 Состояния загрузки / ошибки / пусто

if (initialLoading) return <CircularProgress />;
if (initialError)   return <Alert severity="error">{initialError}</Alert>;
if (initialData.length === 0) return <Alert severity="info">Нет данных</Alert>;

11.6 Механика ленивой загрузки детей

  1. Клик на стрелку → expanded меняется.
  2. useEffect в Tree.tsx видит: строка раскрыта, getSubRows(row) === undefined, canExpand(row) === true → вызывает loadChildren(row).
  3. Пока промис не разрешён — isLoading = true, MRT показывает лоадер.
  4. Ответ → withSubRows(row, children) → setData → дети рендерятся.
  5. Ошибка → finally снимает isLoading, subRows остаётся undefined → повторный клик отправит запрос снова.

11.7 Параметр canExpand при серверной загрузке

ВариантКодКогда
Всегда truecanExpand={() => true}Сервер не отдаёт флаг «есть дети»
По флагуcanExpand={(row) => row.hasChildren}В листинге есть hasChildren
Если canExpand вернёт false, стрелки не будет — пользователь не сможет инициировать загрузку детей. Для серверной модели обычно используют () => true.

11.8 Чек-лист интеграции

  1. Создать api.ts с fetchRoots(signal) и fetchChildren(row).
  2. В ParentPage — состояния initialData, initialLoading, initialError.
  3. В useEffect загрузить корни с AbortController.
  4. Передать initialData в <MRTTree initialData={initialData} ... />.
  5. Передать loadChildren={fetchChildren}.
  6. Поставить canExpand={() => true}.
  7. Добавить рендер состояний: загрузка / ошибка / пусто.
  8. Проверить, что повторный клик после ошибки отправляет запрос снова.
